3.2 Paddle webhook (N1)

Route registers a content-type parser with parseAs: 'buffer' for that path only. Signature: Paddle-Signature ts + one or more h1 (rotation) over exactly ts:rawBody, constant-time compare, ±5 minute tolerance. Never re-stringify. Bad signature → generic 401. Duplicate event id → 200 no-op.

3.3 Internal admin (:3001, header x-admin-secret)

  • GET /internal/admin/users?q=
  • POST .../accounts/:id/suspend|unsuspend|plan|revoke-keys
  • POST .../sessions/:id/force-logout
  • GET .../failing-webhooks
  • POST .../invites
  • Manual review flagging (refunds / paused / mismatched events)
  • Prometheus metrics

CLI wrapper: scripts/admin-cli.ts → pnpm admin -- <cmd>. Actions audit-logged; no message bodies.

11. Cross-cutting concerns

11.1 Security

  • Argon2id passwords; hashed tokens; AES-GCM auth state & outbox payloads
  • Pino redaction paths for auth headers/cookies/tokens/passwords/text
  • Turnstile on auth forms; rate limits (IP / failed auth / account / route)
  • Webhook URL SSRF checks; signed outbound deliveries
  • Gitleaks + Playwright e2e in CI; workflow default permissions: contents: read; no pull_request_target
  • Preflight rejects placeholders and console email in prod
  • Public tree: security-pass / Claude handoff removed (private ops pack only)

11.2 Multi-tenancy

  • All session/message/webhook queries scoped by account_id
  • Cross-account access → 404 (or 403 where policy says so)
  • Tests: phase-2 integration, session-ux, worker tenant-isolation

11.3 Privacy logging rule

Do not put secrets, refresh tokens, PAT/session keys, or message bodies in logs or plaintext DB columns meant for ops. Encrypted blobs are OK; audit meta must stay metadata-only.
